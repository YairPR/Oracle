## 2. Núcleo Criptográfico — Refactor del Primitivo

### 2.1 Decisión Arquitectónica: `f_ff1_cifrar_raw`

> [!IMPORTANT]
> **Decisión de diseño clave:** Claude extrajo el algoritmo FF1 como un primitivo público parametrizado por clave y tweak (`f_ff1_cifrar_raw`), manteniendo el wrapper de producción (`f_ff1_cifra`) como un oneliner que pasa la clave derivada del pepper.

```sql
-- PRIMITIVO (público, L84 spec, L191-283 body): clave y tweak explícitos
FUNCTION f_ff1_cifrar_raw(p_digitos IN VARCHAR2, p_clave IN RAW, p_ajuste IN RAW)
  RETURN VARCHAR2;

-- WRAPPER (privado, L289-292 body): usa la clave AES derivada del pepper de la campaña
FUNCTION f_ff1_cifra(p_digitos IN VARCHAR2, p_ajuste IN RAW) RETURN VARCHAR2 IS
BEGIN
  RETURN f_ff1_cifrar_raw(p_digitos, f_clave_aes, p_ajuste);
END;
```

**Evaluación de esta decisión:**

| Criterio | Veredicto |
|---|---|
| **Fuente única de verdad** | ✅ Un solo algoritmo FF1, no dos copias |
| **Testabilidad** | ✅ El test llama al primitivo real del motor con clave NIST |
| **No duplicación (anti-drift)** | ✅ Si alguien modifica el algoritmo, los tests lo detectan |
| **Seguridad** | ✅ El descifrado NO viaja en el paquete de producción |
| **Compatibilidad** | ✅ Firmas públicas de `func_*` intactas (el wrapper es privado) |

### 2.2 Conformidad NIST SP 800-38G — Verificación Exhaustiva

He verificado [`f_ff1_cifrar_raw`](file:///C:/Users/yair.purisaca/Documents/Claude/FF1/06_dm_pkg_func_mask.sql#L191-L283) paso a paso contra el Algoritmo 7 del NIST:

| Paso NIST | Líneas | Implementación | Correcto |
|---|---|---|---|
| 1. `u = ⌊n/2⌋`, `v = n − u` | L219-222 | `TRUNC(l_n/2)`, `l_n - l_u` | ✅ |
| 2. `b = ⌈⌈v·log₂(radix)⌉/8⌉`, `d = 4·⌈b/4⌉+4` | L225-226 | `CEIL(CEIL(l_v * 3.32192809488736) / 8)` | ✅ |
| 3. Bloque P = 16 bytes | L229-234 | `'010201' \|\| radix(3) \|\| '0A' \|\| u(1) \|\| n(4) \|\| t(4)` | ✅ |
| 4. 10 rondas `i = 0..9` | L237 | `FOR i IN 0 .. 9 LOOP` | ✅ |
| 4a. Q = `T \|\| [0]^(-t-b-1 mod 16) \|\| [i] \|\| [NUMradix(B)]^b` | L239-243 | Padding correcto, `f_num_hex` para serialización | ✅ |
| 4b. PRF = AES-CBC-MAC(K, P\|\|Q) → últimos 16 bytes | L246-250 | `ENCRYPT_AES128 + CHAIN_CBC + PAD_NONE`, `SUBSTR(cifr, -16)` | ✅ |
| 4c. Expansión S a d bytes | L253-264 | ECB con XOR counter (correcto) | ✅ |
| 4d. `y = NUM(S) mod radix^m` (Horner) | L267-273 | `MOD(l_y*256 + byte, l_mod_m)` byte a byte | ✅ Preciso |
| 4e. `c = (NUM(A) + y) mod radix^m`, swap | L276-278 | `MOD(TO_NUMBER(l_a) + l_y, l_mod_m)` | ✅ |
| 5. Resultado = A \|\| B | L282 | `RETURN l_a \|\| l_b` | ✅ |

**Parámetro clave:** La clave AES se pasa como `p_clave` (parámetro explícito), NO como `f_clave_aes` embebido. Esto permite que los tests validen con la clave NIST `2B7E151628AED2A6ABF7158809CF4F3C` directamente sobre el código de producción.

### 2.4 FF1.Decrypt (Algoritmo 8) — Solo en Test

**Implementación verificada en [`f_ff1_descifrar_raw`](file:///C:/Users/yair.purisaca/Documents/Claude/FF1/tests/pkg_dm_ff1_test.sql#L77-L156):**

| Diferencia vs. Encrypt | Implementación | Correcto |
|---|---|---|
| Rondas en orden inverso (`9..0`) | `FOR i IN REVERSE 0 .. 9 LOOP` | ✅ |
| Q usa `NUM(A)` en vez de `NUM(B)` | `f_num_hex(TO_NUMBER(l_a), l_bnum)` | ✅ |
| `c = (NUM(B) − y) mod radix^m` | `MOD(TO_NUMBER(l_b) - l_y + l_mod_m, l_mod_m)` | ✅ |
| Swap inverso: `B←A`, `A←C` | `l_b := l_a; l_a := LPAD(...)` | ✅ |
| Normalización MOD negativo Oracle | `+ l_mod_m` antes del `MOD` | ✅ **Crítico** |

> [!NOTE]
> **Detalle sutil:** Oracle `MOD` sigue el signo del dividendo (`MOD(-3, 10) = -3`), a diferencia de Python. La normalización `+ l_mod_m` garantiza que el resultado sea siempre positivo. Claude verificó esto con 30k valores en sandbox antes de portarlo. ✅
